# 2026-09-11 Nikkei verification code UI

The existing settings/integration screen now accepts the six-digit Nikkei verification code. Login states distinguish code required, invalid and expired from other manual challenges. The code is sent only by an explicit authenticated same-origin POST, is not persisted, and is not included in error messages. SQLite locks prevent concurrent submissions and web/worker login collisions; background login never retries these challenge states. Submission is rate limited to five attempts per minute in each web process.

The server checks the saved login tab, the exact Nikkei ID origin and `/login/challenge`, and the six visible fields before typing. It uses real browser input events and verifies the resulting login page. CAPTCHA and other manual challenges are not handled by the code form.

When article capture stops for authentication, the article offers a settings link. Its ID is remembered only in that browser tab's sessionStorage for 30 minutes. On login success, settings consumes the pending request before one retry and displays a link to read the article or retry a failed import. No code is stored in sessionStorage. If browser storage is unavailable, return to the article to retry manually.
