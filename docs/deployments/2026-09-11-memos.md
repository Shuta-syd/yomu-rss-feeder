# 2026-09-11 Memos integration

Research: https://memos.my-house.tokyo/api/v1/instance/profile responded with version=dev, commit=unknown, needsSetup=false. The exact deployed release is therefore not established. Local sibling Memos source (proto/api/v1/memo_service.proto and integrations/memos-mcp/src/memos-client.ts) exposes /api/v1/auth/me, memo GET/POST/PATCH, caller-supplied memoId, content-only updateMask and username-based users. The official API-access documentation confirms Bearer personal access tokens (https://usememos.com/docs/integrations/api-access). Root SSH was denied; the restricted memos-prod deployment check succeeded. No Memos deployment, database access or authentication changes were attempted.

Yomu settings /settings?tab=integration now has a Memos connection card. A successful auth/me check is required before persisting settings. The PAT is encrypted using Yomu's existing AES-GCM key, never returned to the browser, and never forwarded automatically to a changed origin. Requests require an HTTPS root URL, use existing URL/DNS safety validation, disallow redirects, time out, bound response sizes and map failures without exposing upstream bodies or credentials. The existing ALLOW_PRIVATE_FEED_URLS switch still governs private-address allowance.

Article flow: open メモ, then Memosに保存・編集. Existing local autosaved notes are retained. Initial Memos draft copies the current note; user-selected tags and optional already-generated summary are assembled with the title/source URL. The user can review the composed Markdown before saving. New memos are PRIVATE. Existing remote memos are fetched into a full Markdown editor with a Memos link; PATCH changes content only, retaining visibility and other fields. No automatic transfer of old notes and no AI calls were added.

Identity is deterministic: yomu- plus 30 SHA256 hex characters over instance origin, verified user resource name and article ID. This provides stable article/memo association and retry-safe creation with Memos's unique caller-supplied ID, without database migrations. If a create response is lost, reopen/reload to recover the existing memo; do not create a random replacement ID. Changing instance/account isolates the association.

Before updates, re-fetch the memo and compare a hash of its content to the loaded version. Account changes, remote content changes/deletions, other owners and overlapping Yomu saves are rejected. The local Memos proto has no atomic conditional-update/ETag field: a narrow GET-to-PATCH race with an external Memos editor remains. This is optimistic conflict detection, not strict cross-app locking. Do not claim atomic protection. A future Memos-side compare-and-swap endpoint would be needed for that guarantee.

Dirty editor content is retained in per-article sessionStorage (when available), scoped to connection identity and the original content version. Restore keeps the old version so remote edits are still detected. Reload requires confirmation before discarding dirty text. Save/reload only removes the unchanged draft captured when the request started, avoiding removal of newer drafts from a reopened editor.
