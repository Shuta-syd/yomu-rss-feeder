# Yomu

AI搭載のセルフホスト型RSSリーダー。Gemini / OpenAI / Anthropic でフィード記事の要約・翻訳を生成できる。

## 特徴

- **AI要約・翻訳** — 2段階処理 (自動要約 + 詳細翻訳)、ストリーミング表示対応
- **マルチLLM** — Gemini / OpenAI (GPT-4o系) / Anthropic (Claude) を混在運用可能
- **全文取得** — RSSが抜粋のみの場合、Readabilityで元記事から全文抽出
- **OPML対応** — インポート/エクスポート
- **PWA** — ホーム画面追加、Web Pushで新着通知
- **認証** — UID (10桁数字) + パスワード、セッションcookie
- **UI** — 3カラムレイアウト、ライト/ダーク切替、記事ビュー幅のドラッグリサイズ
- **セルフホスト** — Docker ComposeでWeb/worker分離運用

## 技術スタック

- Next.js 16 (App Router) / React 19 / TypeScript 5.7
- SQLite (WAL) + Drizzle ORM + FTS5全文検索
- Tailwind CSS 4 + next-themes
- node-cron (5分tick) のworkerで自動取得
- Vitest (97テスト)

## 起動

Docker Compose中心の運用。Makefileで一発起動できる。

### 開発 (dev コンテナ)

```bash
make dev       # コンテナ起動 + pnpm install + db migrate + dev server (デーモン)
make logs      # 開発サーバーのログ表示
make shell     # コンテナに入る
make down      # 停止
```

http://localhost:3000 で起動。初回アクセスで `/setup` に誘導される。

### 本番

```bash
make prod-up       # docker-compose.yml でビルド・起動
make prod-logs
make prod-down
```

### 必須環境変数

```bash
ENCRYPTION_KEY=<64桁のhex文字列>  # openssl rand -hex 32 で生成
VAPID_PUBLIC_KEY=<Web Push用>    # make vapid-keys で生成
VAPID_PRIVATE_KEY=<Web Push用>
```

APIキー (Gemini / OpenAI / Anthropic) は初回セットアップ後、設定画面で登録する。AES-256-GCMで暗号化保存される。

ローカルネットワーク上のフィードURLを取得したい場合のみ、`ALLOW_PRIVATE_FEED_URLS=true` を設定する。未設定時はSSRF対策として private / loopback / link-local 宛のURLを拒否する。

### RSS同期の運用設定

本番で使用している外向きDNS設定を維持するため、app/workerは既定で `1.1.1.1` と `8.8.8.8` を使用します。必要に応じて `YOMU_DNS_PRIMARY` / `YOMU_DNS_SECONDARY` で変更してください。

本番Docker Composeでは、Web応答を担当する `app` とRSS同期/AI処理を担当する `worker` を分けて起動する。`app` 側では自動同期を起動せず、重いJSDOM解析やLLM処理でWeb応答が詰まるのを避ける。

障害時に自動同期を止める場合は `YOMU_AUTO_SYNC_ENABLED=false` を設定して再起動する。この設定は `worker` にだけ適用され、Web UI/APIはそのまま起動する。

```bash
YOMU_AUTO_SYNC_ENABLED=true
YOMU_DNS_PRIMARY=1.1.1.1
YOMU_DNS_SECONDARY=8.8.8.8
YOMU_SYNC_MAX_DURATION_MS=480000
YOMU_SYNC_LOCK_TIMEOUT_MS=600000
YOMU_MAX_FEED_ITEMS=200
YOMU_MAX_FULL_CONTENT_FETCHES_PER_FEED=20
YOMU_MAX_ITEM_HTML_CHARS=200000
YOMU_STAGE1_PENDING_LIMIT=50
```

## セルフホストデプロイ (Proxmox等)

1コマンドで環境構築・自動デプロイcron設定まで完了:

```bash
# サーバー側 (root or sudo)
curl -fsSL https://raw.githubusercontent.com/<user>/yomu-rss-feeder/main/scripts/setup.sh | bash
```

または clone してから:

```bash
git clone https://github.com/<user>/yomu-rss-feeder.git /opt/yomu
cd /opt/yomu
./scripts/setup.sh
```

`setup.sh` は以下を実行:
- Docker / git インストール (未導入時)
- `/opt/yomu` に clone

- `docker compose up -d --build`
- 5分おきに `git pull` + 再ビルドする cron を登録

以降、ローカルで `git push` するだけでサーバー側に自動反映されます。

`qa:setup` は初回のみ `data/yomu.db` を `data/yomu-qa.db` に複製し、

複製先のセッションとLLM APIキーは削除される。
QA用DB、認証情報、セッションはGitへコミットしない。

### 記事の自動分類

新着記事は全フィードで Stage1 の処理待ちに入り、worker の定期処理でジャンル・業界・テーマを付与する。
フィードのAI設定がONなら要約・タイトル翻訳と同じ呼び出しで分類し、OFFなら本文先頭6,000文字までで分類のみ行う。
どちらも設定画面のStage1プロバイダ・モデルを使う。分類だけでもAPI利用量が発生する。
分類は既存の `ai_tags` に `ジャンル:` / `業界:` / `テーマ:` 接頭辞付きで保存される。
過去の完了・スキップ記事は自動再処理しない。失敗記事は詳細画面から手動再実行できる（手動の翻訳操作では要約も生成する）。
動作にはAPIキーと稼働中のworkerが必要。`YOMU_AUTO_SYNC_ENABLED=false` のWeb単体では定期処理しない。

### AI費用と予算

設定 → AI →「AI費用・予算」で、この環境の今日・今月の概算費用、モデル別トークン数、最近の呼び出しを確認できます。初期上限は日額300円・月額3,000円、換算は1ドル150円。0円で新しい呼び出しを停止します。分類・要約・詳細翻訳を共通で計上します。

呼び出し前にSQLiteの即時トランザクションで概算を予約し、APIの使用量で精算します。Geminiの思考トークンも出力に含めます。通信失敗やストリーム中断など使用量が不明な場合、予約額を残します。上限待ちの自動分類はpendingを保持し、次回の定期処理で再判定します。SDKの暗黙の再試行は無効です。

これは登録単価による概算制限で、請求元の厳密な上限ではありません。導入前の利用、同じキーを使う別環境、税・無料枠・割引は含みません。未登録モデルは単価を設定するまで呼び出せません。単価は[公式料金](https://ai.google.dev/gemini-api/docs/pricing)で再確認してください。導入には `db:migrate`（0009_ai_usage.sql）の適用と、Web・worker両方の再起動が必要です。

### 本文の表示と日経電子版

記事本文の表示時にナビゲーション・フォームを除き、日経の記事末尾に混入した購読案内・自動関連記事を整えます。元の保存データは変更せず、「取得した本文をそのまま表示」で比較できます。画像・長いURL・表は本文領域からはみ出さないよう調整しています。

購読済みブラウザーのログインは、現在のサーバー側RSS/本文取得には引き継がれません。2026-09-10に確認した[日経コンテンツ利用規定](https://www.nikkei.com/info/copyright.html)は、自動取得・保存および生成AIの参照用の収集等に事前許諾を求めています。購読ログインはChromeで行います。下記の明示操作によるブラウザー本文取り込みを追加しました。新着の会員本文を自動巡回する機能はありません。


### 購読済みブラウザーから日経本文を取り込む

1. Yomuを実行しているマシンで連携用Chromeを起動します。専用プロファイルを使い、デバッグポートを外部公開しないでください。
   ```sh
   google-chrome --remote-debugging-address=127.0.0.1 --remote-debugging-port=9222 --user-data-dir="$PWD/data/yomu-browser-profile"
   ```
2. Yomuの実行環境に `YOMU_BROWSER_CDP_URL=http://127.0.0.1:9222` を設定し、`db:migrate`（0010）を適用してWebを再起動します。未設定の環境では連携は無効です。
3. そのChromeで日経にログインし、対象記事を開きます。設定 → 連携でChromeへの接続状態を確認できます。
4. 同じChromeでYomuの対象記事を開き、「ブラウザーの本文を取り込む」を押します。

開いている同一URLの記事から、画面に表示された本文領域だけを取り込みます。本文取り込み処理はCookie・パスワードや、非表示コンテンツ・埋め込みJSONを読み取りません。自動ログイン用の登録情報は、下記の別設定で暗号化保存します。ログイン・購読案内が表示されている記事は保存せず、既存の本文を保持します。記事構造が変わると読み取りに失敗する場合があります。

初回の元本文は `article_browser_imports` にバックアップし、記事には取り込み日時を表示します。取り込みにAIは使いません。古い要約はクリアし、自動分類・要約を既存の予算内で更新します。AI実行中の記事への取り込みは拒否します。

現在の接続先はループバック限定です。自宅サーバーへ展開する場合は、サーバー側でChromeを起動するか、安全なトンネルを別途構成する必要があります。ローカルPCのChromeへ自宅サーバーからそのまま接続できるわけではありません。

検証では、未ログインの実記事が拒否されること、別記事・非表示本文を取り込まないこと、保存・元本文保持・古い要約の無効化を確認します。2026-09-11、購読ログイン後の日経2記事で実機検証済みです。住宅ロボット記事（685文字・6段落・画像1枚）とiPhone記事（1,762文字・17段落・画像5枚）の保存・Yomu表示を確認し、両記事の全段落が元のブラウザー表示と一致することをハッシュで照合しました。これはローカル環境の検証で、本番サーバーへの展開は別途必要です。


### 日経への自動ログイン

設定 → 連携で日経ID（メールアドレス）・パスワードを登録し、自動ログインを有効にします。既存の `ENCRYPTION_KEY` によるAES-256-GCMで両方を暗号化保存し、設定取得APIは登録有無・処理状態だけを返します。「今すぐ接続確認・再ログイン」で明示的に確認できます。2026-09-11、ユーザー登録後に未ログインの独立したChromeコンテキストで自動ログイン成功を確認しました。同条件の未入力コンテキストはログイン要求になることも確認し、既存セッションの流用でないことを照合しています。

workerの5分間隔の処理から接続確認を呼びます（ログイン正常時は15分間隔まで間引き）。本文取り込みでログイン切れを検出した場合も、自動再ログイン後に記事を再読み込みします。ログイン済みならパスワードを送信しません。専用タブを使い、ユーザーが読んでいるタブをログイン画面へ置き換えません。

日経IDの正規ログイン画面でメール・パスワードを各1回入力します。追加認証・CAPTCHA・入力エラー・画面遷移の停滞では停止し、手動確認が必要な状態を表示します。失敗後のバックグラウンド再試行は行わず、登録情報の更新または設定画面からの明示的な再試行を待ちます。SQLiteの処理ロックでWebとworkerの同時実行を抑制します。通信不通時は時間を空けて再確認します。

「登録情報を削除」は保存したメール・パスワードを削除し、自動ログインを停止します。Chrome内に残るログイン状態からのログアウトは別操作です。導入後はWebだけでなくworkerも再起動してください。本番側でのChromeの用意・接続設定は引き続き必要です。

再確認時の注意：日経のメール入力画面には、ゼロサイズの親要素に隠れたパスワード入力欄があります。`getClientRects()` だけでは表示中と誤判定するため、祖先の表示状態とクリッピング領域も確認します。ログイン画面変更時には `login-dom.test.ts` と実際の画面で両方のステップを再検証してください。

ログイン確認時は、新しいタブの `about:blank` を追加認証と誤判定せず、遷移完了まで待機します。この初期遷移は `login-dom.test.ts` で検証しています。

### 分類の組み合わせと保存条件

記事一覧の「絞り込み」を開くと、「ジャンル」「業界」「テーマ」を各1つ選択できます。「この条件で表示」で適用し、閉じるだけなら変更を破棄します。デスクトップでは中央のダイアログ、スマートフォンでは下から開くパネルに表示します。選択済みの分類は一覧上のチップから個別に解除できます。選んだ軸のすべてに一致する記事を表示します。分類条件はページ送り・更新でも引き継ぎ、URLに保存してリロード時に復元します。

「条件を保存」で分類・検索語・未読／既読・お気に入り表示・対象フィード（またはカテゴリ）を名前付きで保存できます。保存条件のボタンで一括適用し、「管理」を押すと表示される×で削除します。同名は重複登録できず、最大30件です。条件はSQLiteに保存され、同じYomuサーバーへログインする端末間で共用できます。分類済みのラベルを利用するため、この絞り込み・保存にAI費用は発生しません。

本番反映時は `0011_saved_filters.sql` を `db:migrate` で適用してください。APIは従来の単一 `classification` と、複数の同名パラメーターによるAND指定に対応します。分類による絞り込み中の一括既読は、従来どおり対象の取り違えを避けるため無効です。

### 重複記事の表示

「すべて」とカテゴリの記事一覧にある「重複記事をまとめる」は既定でONです。単一フィードとお気に入りではこの操作を表示せず、記事を個別に表示します。この端末の選択を保存し、OFFで従来の一覧に戻せます。対象は現在の検索・フィルタで読み込み済みの記事だけで、ページを追加読み込みすると再判定します。先頭の記事を代表にし、残りは「関連記事」から個別に開けます。選択中の関連記事は自動展開します。記事・既読状態・一覧の総件数を集約によって変更することはありません。

URL一致（フラグメントと既知の計測パラメーターのみ除去）、または元タイトルの全半角・空白の正規化後の一致でまとめます。タイトル一致は24文字以上、公開日時が両方あり48時間以内の場合だけです。翻訳タイトルやAIによる類似判定は使いません。数字・否定表現・URLの記事識別パラメーターが異なる場合や、同じ業界というだけの記事をまとめないことを `article-groups.test.ts` で確認できます。処理はブラウザー内で完結し、追加のAI費用は発生しません。

### あとで読む

一覧と本文の「あとで読む」から保存・解除できます。お気に入り・既読状態とは独立してサーバーのSQLiteに保存し、記事を読んでも自動解除しません。サイドバーの件数は既読・未読を合わせた保存数で、30秒ごとと記事更新後に再取得します。入口を押すと検索・分類・既読条件を解除して全保存記事を表示します。`?view=later` で直接開けます。この画面では重複集約と一括既読は無効です。

導入には `0012_read_later.sql` の適用とWeb・workerの再起動が必要です。ローカルQAのDBには適用済みです。記事を削除する機能ではなく、AI呼び出しもありません。フィード自体を削除した場合は、従来どおりそのフィードの記事も削除されます。

### 本番の日経連携ブラウザー

`docker-compose.browser.yml` を追加すると、本文取得用 Chromium がサーバー内で動きます。CDP ポートは外部公開しません。設定 → 連携で日経のログイン情報を登録し、自動ログインを有効にしてください。記事の「本文を取り込む」で対象ページを開き、表示された本文を取得します。一時タブは取得後に閉じます。

```sh
docker compose -f docker-compose.yml -f docker-compose.prod.yml -f docker-compose.browser.yml up -d --build
```

既存環境で追加の Compose override を使用している場合は、その指定も維持してください。2026-09-11 の稼働環境固有の起動方法は `docs/deployments/2026-09-11-nikkei.md` を参照してください。

ログイン情報は Yomu の暗号鍵で暗号化され、ログイン状態は `yomu-browser-profile` ボリュームに保存されます。バックアップ対象はデータベース、既存の暗号鍵、ブラウザープロファイルです。追加認証が要求された場合は自動処理を停止します。本文取得そのものでは AI API を呼びませんが、取得後の記事の再分類・要約には既存の AI 予算設定が適用されます。

### Jev検索（任意）

設定 → AI →「Jev検索」でTypeSafeのAPIキーを登録し、スイッチをONにして保存する。
検索欄に「面接について」などを入力してEnterまたは検索ボタンで実行する。
候補検索にはStage1に設定したAIのキー・モデルを使う。Jevキーは既存のAES-GCM保存方式で暗号化し、ブラウザーには返さない。

Stage1が最大8個の関連語を作成し、タイトル・日本語タイトル・短い要約・タグ・本文から候補を収集する。
候補は語の一致を重み付けした上位100件。指定したフィード・分類・既読・保存条件を維持する。
Jev (`jev-1.13.0`) が検索文と各候補のタイトル・要約・本文抜粋から関連度を0〜3で判定し、2以上を関連度順に表示する。
候補に入らない記事や抜粋外の内容は見落とす可能性があり、全記事の意味検索を保証するものではない。
日本語の実際の精度は自分の記事で確認すること。画面に判定した候補数と候補総数を表示する。

同一条件の検索結果は5分間サーバーメモリに保持し、ページ送りや再検索で再課金しない。
カーソルが期限切れになったら「最初から再検索」を使う。検索中の一覧は定期更新で並べ替えない。
Jevまたは候補検索用AIの失敗は画面に表示し、その検索だけ通常検索へ切り替えられる。
スイッチOFFでは従来の全文検索を使い、AI呼び出しを行わない。

候補検索とJev判定は既存のAI予算に計上する。Jev登録単価は2026-09-29確認の入力100万トークンあたり$0.042、出力無料（[公式](https://docs.typesafe.ai/models)）。
検索全体に60秒の期限、Jevの各リクエストに15秒の期限を設定する。新規検索はプロセスあたり同時2件、Jev判定は各検索で同時4件まで。
予算・料金は概算で、通信失敗時は使用量が分からない予約額を保持する。
